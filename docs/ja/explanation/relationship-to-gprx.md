# gprx との関係

cxxgpr は、Rust ライブラリ [gprx](https://github.com/YUKIKEDA/gprx) の **Exact GPR** モデルを C++23 へ移植したものである。このページでは、何を引き継ぎ、何を意図して外し、C++ であるために何が変わったかを説明する。`gprx` を知っている読者や、いま使っているモデルを cxxgpr で置き換えられるかを知りたい読者に向けて書いている。

:::{note}
このページの `gprx` についての記述は、cxxgpr プロジェクトが自らの移植範囲と、`gprx` の出力に対する検証について記録していることに限る。`gprx` の挙動は、このページのために独立に再確認していない。それ以外のことは `gprx` のドキュメントを参照してほしい。
:::

## 移植したもの

移植の対象は、`gprx` の Exact GPR にあたる部分である。$n \times n$ の共分散行列全体を、近似せずに分解するモデルである。cxxgpr の言葉で言うと次のとおりである。

| 領域 | 移植した内容 |
|---|---|
| モデル | `Gpr`（学習器）と `FittedGpr`（学習済みモデル）。`fit`、`factor`、`predict`、`predict_covariance`、`sample`、`loo_predict`、勾配とヘッセ行列つきの周辺尤度、再当てはめ、パラメータへのアクセス |
| カーネル | 組込みの 10 種の葉カーネル、カーネルの和と積、ユーザー定義の `Custom` の葉、*与えた*二乗距離からの学習（`DistanceKernel`） |
| 前処理 | 入力・目的変数の変換。恒等、標準化、min-max スケーリング、パイプライン、列ごとの変換 |
| 精度 | `DoublePrecision`、`SinglePrecision`、反復精緻化つきの `MixedPrecision` |
| 数値計算 | `KernelExp` による正確な指数関数と高速な指数関数の選択、観測ノイズと数値ジッターの分離 |
| 最適化 | 5 つの最適化器：`Lbfgs`、`NelderMead`、`TrustRegion`、`FastSimulatedAnnealing`、`Fixed` |
| 永続化 | `config.json` と `model.safetensors` のディレクトリ、`save`、`save_with_factor`、`LoadedGpr`、`PersistRegistry` |

最適化器は cxxgpr の内部で実装してあり、`gprx`（とそれが使う argmin ライブラリ）が用いるアルゴリズム仕様に従う。外部のソルバーライブラリはリンクしない。事後標本や最適化のリスタートに使う乱数生成器 `Xoshiro256++` は、同じシードに対して `gprx` の生成器と同じ列を出すように仕様が定められている。これは、どの OS、どのビルド構成でも変わらない。

## 移植しなかったもの

`gprx` の次のモデルは、意図して cxxgpr の範囲外にしてある。

- **`Sgpr`** と **`Svgp`**：少数の誘導点でデータを要約し、厳密推論の 3 乗のコストを避けるスパース近似。
- **`OnlineGpr`**：観測を 1 つずつ加えて更新する Exact GPR。別の分解（LDLT）と、データ点の安定した識別子に依存する。どちらも cxxgpr にはない。
- 結果として、スパースモデルにしか存在しない、誘導点の座標についての微分も含まない。

理由は実務的である。cxxgpr は、すべてのモデルを部分的に再現するより、1 つのモデルを完全に再現することを目指している。検証された数値、安定した API、決定的な結果、文書化されたファイル形式を備えた、完全な再現である。厳密モデルは、スパース手法を評価するときの基準でもある。忠実な厳密モデルを核にしておくのが、最初の土台として役に立つ。数千点を超える規模を扱うなら、点を間引くか問題を分割するか、別のライブラリのスパース手法を使ってほしい。

永続化も同じ境界で決まる。ディレクトリ形式は、`gprx` の Exact GPR の永続化形式と本質的に互換である。ただし、オンラインモデルの LDLT 因子や点の識別子を使うチェックポイントと、スパースモデルのチェックポイントは、読み込み時にエラーとして拒否される。

## C++ であるために決まったこと

| 項目 | cxxgpr の扱い |
|---|---|
| エラー | `[[nodiscard]] std::expected<T, GprError>`。例外は API の境界を越えない |
| 失敗しうる構築 | `static std::expected<T, GprError> create(...)` ファクトリ。失敗しない型は普通のコンストラクタ |
| 不変性 | `Gpr::fit` と `Gpr::factor` は `const`。当てはめが失敗しても、学習器は変わらない |
| 行列 | 列優先の `std::span<const double>` と形状、または所有しない `MatrixRef`。{doc}`../how-to/prepare-data` を参照 |
| 線形代数と並列化 | Eigen と OpenMP。どちらも非公開で、結果はスレッド数に依存しない |
| 利用者から見える依存 | なし。Eigen、nlohmann/json、OpenMP は公開ヘッダに現れない |

はっきり述べておくべき帰結が 2 つある。第 1 に、API は C++ らしい形をとる。カーネルは Rust のトレイトではなく、`KernelSpec` と `with_*` ビルダーメソッドで組み立てる。第 2 に、cxxgpr は再現性を機能として扱う。同じ入力からは、何スレッドで走らせても同じビット列が得られる。ゼロアロケーションの予測経路（`predict_into`）は、ウォームアップ後にメモリを確保しない。{doc}`determinism-and-performance` を参照してほしい。

## gprx への近さをどう検証するか

近さは、仮定せずに検査している。cxxgpr のテストは、固定したハイパーパラメータ、L-BFGS による最適化、1 点抜き予測のそれぞれについて、当てはめ結果と予測値を、`gprx` から記録した出力、`scikit-learn` ライブラリ、解析解と比べる。独立な実装が浮動小数点で出す結果の差は、小さいはずだが、ゼロにはならない。同じ初期点から始めても、最適化の経路はわずかに異なりうる。結果を比べるときは、ビットの一致ではなく許容誤差で比べてほしい。

## gprx から移る

モデルの名前は引き継がれている。`gprx` と同じく、`Gpr` が学習器、`FittedGpr` が学習済みモデルである。まず {doc}`../tutorials/first-regression` を読み、続いて {doc}`../how-to/build-kernels` と {doc}`../how-to/choose-optimizer` を使うとよい。C++ の API を形づくった設計原則は {doc}`design-principles` にある。
